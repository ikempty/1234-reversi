# 1234リバーシ

2×2の範囲で1〜4個の駒を合体して置くリバーシです。3個はL字、4個は正方形。

## 今使える機能

- TOP画面から「CPU対戦」または「ランダムマッチ」を選択。
- TOP画面で自分のレートを確認でき、ランキング専用画面を開けます。閲覧だけではマッチングや新規プレイヤー作成は行いません。初めて遊ぶ場合は初期レート1500を表示します。
- CPU対戦はレベル1〜10を選ぶと開始。ランダムマッチは選択すると自動で接続・マッチングを開始（サーバー設定後）。
- ニックネームはTOP画面で入力。ランダムマッチでは入力が必須で、空欄や空白のみでは開始できません。CPU対戦とランキング閲覧は未入力でも利用できます。
- CPU対戦（レベル1〜10）。あなたが黒、CPUが白。
- 2×2の合体スペース、配置プレビュー、手持ち、自動パス、勝敗判定。
- 「戻す」はCPUの応答を含めて、直前の自分の手を打つ前に戻ります。
- ランダムマッチ・匿名プレイヤー・Eloレート・ランキング。Cloudflare Workersの対戦サーバーに接続します。

## 起動

公開先: https://1234reversi.com/ （HTTPS有効）

Cloudflare DNSの `@` はAレコード4件（`185.199.108.153`、`185.199.109.153`、`185.199.110.153`、`185.199.111.153`）、`www` は `ikempty.github.io` へのCNAMEです。5件ともDNS only。GitHub PagesのCustom domainは `1234reversi.com`、Enforce HTTPSは有効です。ドメインを変更するとブラウザの保存領域も変わるため、旧URLの匿名ID・レートは自動では引き継がれません。

GitHub Pagesは `main` ブランチの `docs/` を公開します。画面のコードを変更したら `npm run build:pages` で公開ファイルを更新し、ソースと一緒にコミット・プッシュしてください。

`npm start` を実行し、http://127.0.0.1:4173 を開きます。

`index.html` を直接開いてもCPU対戦は動きます。HTTPで開くとCPUをWeb Workerで動かし、思考中も画面が操作できます。ファイルを直接開く場合はブラウザ互換性のため思考時間を短くします。

## CPUの強さ

- Lv.1: 合法手からランダム。
- Lv.2: 駒数を重視。ときどきランダム。
- Lv.3〜4: 角・危険なマス・盤面の位置を評価。Lv.3にはランダム性あり。
- Lv.5〜10: 相手の応答も探索。レベルに応じて候補数・深さ・思考時間を増やします。

Lv.10の思考予算は通常最大約1.4秒（候補生成等の時間を除く）。難易度は暫定調整で、実力差の保証や対人レートへの換算はありません。

## 無料のオンライン対戦を公開する手順

1. Cloudflareの **Workers & Pagesの契約がWorkers Free** であることを確認します。ドメイン/DNS側のFree表示とは別です。Workers Paidへは変更しません。
2. ローカルで `npm install`、`npm run online:dev` を実行し、2クライアントで接続確認します。ローカル実行はクラウドへ公開しません。
3. `backend/wrangler.jsonc` の `ALLOWED_ORIGINS` にゲームの公開元（例: `https://example.github.io`。リポジトリのパスは含めない）を設定します。
4. 同ファイルの `RANKED_ENABLED` を `"true"` にします。これはゲームの受付設定であり、課金プランを変更するものではありません。
5. 無料プランを確認したアカウントで `npx wrangler login`、`npx wrangler deploy --config backend/wrangler.jsonc` を実行します。ログインは本人が行います。アップグレードを要求された場合は進めず、設定を確認します。
6. 返されたHTTPS URLを `online-config.js` の `REVERSI_ONLINE_URL` に設定します。秘密鍵・APIトークンは書きません。
7. フロント側のHTML/CSS/JSをGitHub Pagesへ公開し、別々のブラウザ/端末で対戦・再接続・レートを確認します。Node.jsのサーバーをGitHub Pagesに配置する必要はありません。

Cloudflare無料枠の上限では対戦・保存が失敗する場合があります。有料への変更・課金契約はこのコードから行いません。ただし利用するCloudflareアカウントが既にWorkers Paidなら、その契約条件が適用されるため事前確認が必要です。独自ドメイン取得・更新料金は別です。

### サーバーの構成

`backend/worker.mjs` が接続元制限、匿名認証、WebSocket通信を担当します。SQLite-backed Durable Objectを1つ使い、マッチング・盤面・レートをまとめて保存します。初期運用での設定を減らすため、D1は不要です。レート更新と対戦終了を同じトランザクションで確定します。

- 登録操作なし。256ビットのランダムな秘密トークンをブラウザに保存し、サーバーにはSHA-256ハッシュだけ保存。
- 待っている相手とマッチ。黒白はランダム。レート差による相手の絞り込みはまだありません。
- 初期レート1500、Elo K=24。CPU対戦はレートに影響しません。
- 手番・持ち駒・形・配置・勝敗をサーバーで検証。ブラウザから勝敗やレートを指定できません。
- 同じ手の再送は盤面のバージョンで拒否。終了/投了の再送でもレートは二重更新しません。
- 1手120秒。切断中も時計は止まらず、時間切れは手番側の負け。再接続で同じ対戦に戻れます。
- 待機中に切断した人は待ち列から外します。対戦中の人は二重マッチしません。
- ニックネームは重複可。成績は内部IDで識別。ブラウザ保存データを消すと元のIDに戻れません。引き継ぎコードは未実装。
- WebSocketの休止機能を使用。無操作の接続を常時動かし続ける構成にはしていません。
- 1 IPにつき1日20件の新規ID作成制限。匿名での作り直し・自作自演対戦を完全に防ぐ仕組みではありません。
- ランキングは対戦済みプレイヤーの上位50人。

### オンライン人数

TOPのランキング左隣に、利用中のブラウザ数を表示します。TOP・CPU戦・ランクマッチのすべてを対象とし、背景タブや画面を閉じた人は除外します。同一オリジンのlocalStorageに保存した独立した匿名IDで複数タブをまとめます。端末・ブラウザ・オリジンが違えば別人数です。

`/presence` と専用の `PresenceLobby` Durable Objectを使います。25秒ごとのWebSocket heartbeatを受信し、直近60秒の接続を集計します。ページ終了時は切断、通信断は次の集計時に期限切れで除外します。取得に失敗した場合は0人とせず「オンライン —」を表示し、自動で再接続します。対戦用トークン、ニックネーム、レートを送らず、DBへの定期書き込みやHTTPポーリングも行いません。過去の訪問数の記録ではなく、現在の利用状況の目安です。

### ランキング初期化とセキュリティ

- `2026-11-25-ranking-reset-1` は依頼に基づく1回限りの成績初期化です。全員のレートを1500、勝敗数を0に戻し、名前・認証情報・進行中の対戦は保持します。完了済み対戦への参照は外します。
- 初期化前のレート・勝敗数・対戦参照はサーバー内の `ranking_reset_backup` に退避します。`ranking_resets` の処理済み記録により、再起動・再デプロイでは再初期化しません。公開のリセットAPIはありません。
- 登録本文は2048バイトまで読み込み、過剰なWebSocket送信は接続を閉じます。想定外の内部エラーはクライアントへ詳細を返しません。本番の接続元にlocalhostは含めず、ローカル開発コマンドでのみ許可します。
- HTMLのCSPで同一サイトのスクリプトと指定した対戦サーバーへの通信を許可します。GitHub PagesではHTMLのCSPだけで他サイトからのiframe埋め込みを禁止できないため、クリックジャッキングの包括的な対策ではありません。
- 匿名IDの作り直し・複数端末での自作自演・外部AIの利用は完全には防げません。全HTTPリクエストへの永続的な流量制限は未実装で、大量アクセスによる無料枠消費は残る課題です。Origin制限はブラウザの接続元を制限するもので、外部プログラムからの不正アクセス全体を防ぐものではありません。
- 認証トークンはlocalStorageに保存します。同一サイト内でスクリプト注入が発生した場合や端末が侵害された場合の漏えいリスク、保存データ削除による成績の引き継ぎ不能は残ります。

## 検証

Node.js 24以上で `npm test`。ゲームルール・CPU・画面の操作処理・SQLite上のマッチング/レート処理を検証します。

`npm run online:check` はCloudflare用のビルド検証のみで、デプロイしません。

`npm run test:online` はビルド後、ローカルのCloudflareエミュレーターにWebSocketで2人を接続し、マッチング・配置・再接続・投了・レート更新を検証します。クラウドへの公開や有料プランへの変更はありません。

ブラウザ目視・複数端末の公開環境テストは別途必要です。
